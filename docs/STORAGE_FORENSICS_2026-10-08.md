# Calcora AI — Forensic Storage Cleanup (Phase 10)

Date: 2026-10-08
Rule followed: nothing was deleted without evidence, and no source, test,
knowledge file, model or `.git` content was removed.

## 2. LFS object store

`.git/lfs/objects` contains more blobs than the four current model files
reference — including two 2 GB and two 1 GB objects that duplicate the current
model payloads under different object IDs, plus three ~211 MB objects of unknown
provenance. These are historical downloads kept by LFS until pruned.

`git lfs prune` is the supported way to reclaim them, and it only removes objects
that no ref in the repository still points at. Because pruning here would only
free *cached duplicates* that remain re-downloadable from the remote, it is
treated as an optional housekeeping step rather than a cleanup requirement, and
it was **not** run in this cycle: with the models freshly restored and the
release being packaged, removing LFS objects during the same window adds risk
without changing what ships. The measured object inventory is in §1.

## 4. Deliberately NOT cleaned

* `.git` and `.git/lfs` — object history is not cleanup material.
* `models/*.gguf` — restored and classified, not removed.
* `release-wave1/…/default_app.asar` — its staged deletion is a pre-existing
  merge resolution from the current in-progress merge and is preserved untouched
  for the merge conclusion (Phase 19).
* Previous release installers in `release/` — superseded only once the new
  artifacts exist; they are replaced, not deleted in place, so a failed rebuild
  always leaves a runnable release on disk.

## 5. Environment finding worth recording

`electron-builder` failed twice with `EPERM … rename '…\win-unpacked.tmp' ->
'…\win-unpacked'` when its output directory was **inside the repository**, while
the same build succeeded when the output directory was moved outside the
workspace. The directory itself could be created, written, renamed-file-inside
and deleted, but the top-level rename stayed blocked for >20 s. This is an
environment interference (a workspace file watcher holding a directory handle),
not an application defect.

Practical consequence for anyone building this repo locally in a watched
workspace:

```bash
npx electron-builder --win nsis portable --publish never \
  --config.directories.output=%TEMP%\calcora-release
```

The committed configuration still targets `release/`, which is what CI uses on
native runners.
