# Calcora AI Tutor — Knowledge Enhancement Policy

## Purpose

Calcora's Tutor is enhanced through **grounded retrieval and verified mathematical knowledge**, not by copying private/proprietary chats or by claiming model training when no fine-tuning has occurred.

## Approved knowledge sources

1. Original Calcora mathematical content.
2. Publicly documented mathematical definitions, formulas, identities, theorems and educational explanations that can lawfully be incorporated.
3. Properly licensed/open mathematical datasets.
4. Public capability research from math products, used only to design Calcora features and tutor behaviors.
5. Deterministic solver outputs and verification traces generated by Calcora.
6. User-provided material when the user has the right to provide it.

## Prohibited ingestion

- Private user conversations from other products.
- Proprietary competitor training datasets.
- Paywalled/copyrighted solution banks copied wholesale.
- Circumvention of access controls.
- Content with unclear licensing when redistribution/storage is required.

## Continuous enhancement pipeline

`Source discovery → license/provenance check → normalize → content hash → deduplicate → mathematical validation → domain/restriction validation → accept/reject → store → embed → retrieve → regression test`

## Tutor quality loop

`User question → classify intent/topic → retrieve relevant concepts/examples → run deterministic calculator/solver when applicable → verify → generate explanation → expose verification state → optionally create practice → record learning signal`

The model is an explanation/tutoring layer. Deterministic engines remain authoritative for supported computation.

## Required Tutor behaviors

- answer-first for quick questions
- definitions with notation and intuition
- step-by-step derivations
- named rule/theorem per important transformation
- alternative methods when valid
- progressive hints
- Socratic questioning
- first-error detection
- domain/restriction awareness
- counterexamples for misconceptions
- practice generation only after deterministic validation where possible
- multilingual explanations while preserving canonical mathematical notation

## Languages

The Tutor response contract currently registers 26 languages. Mathematical notation stays canonical while explanatory language is localized.

## Automatic enhancement

New knowledge must never silently become authoritative. New records enter a pending/validation state, receive provenance and content hashes, and only become retrieval candidates after validation. Embeddings are derived from accepted content; they are not a substitute for verification.
